# 0003. Logs

- **Status:** Provisional
- **Authors:** @bhatnagar-afk
- **Created:** 2026-11-15
- **Milestone:** M3

## Summary

KubeRoot shows container logs in the detail panel: for one pod, or merged across every pod of a
workload (Deployment, StatefulSet, DaemonSet, ReplicaSet, Job). Logs stream live (follow), can
show the previous (crashed) container, can be searched and filtered in place, and can be
downloaded to a file. Workloads also get a **Pods** tab listing their pods, which proposal
[0002](0002-resource-browsing.md) deferred to M3 (follow-up 1), because both features need the
same "pods of a workload" lookup.

## Motivation

After "what is running?" (M2), the next question is almost always "why is it failing?", and
the answer is usually in the logs. `kubectl logs` handles one pod at a time, makes you find the
pod name first, and loses its place when a container restarts or the connection drops. A
desktop client can do better: open logs from the object you are already looking at, follow a
whole Deployment, and keep streaming across restarts and reconnects.

### Goals

1. A **Logs** tab in the detail panel for pods and workloads.
2. **Follow** (live streaming) with auto-scroll that pauses when the user scrolls up.
3. Options: container (including init and ephemeral containers, or all containers), tail
   lines, since, **previous** container, timestamps on/off, line wrap.
4. **Workload logs:** lines from all of a workload's pods in one view, prefixed with pod and
   container, following pods as they are created and deleted.
5. **Search:** highlight matches with next/previous, optionally show only matching lines;
   plain text or regex, case-sensitive or not.
6. **Download** the full log of the current target to a file.
7. Streams survive container restarts (while following) and connection drops (resume where
   they stopped, without duplicate lines).
8. A **Pods** tab for workloads, live, using the same table pipeline as M2.
9. A noisy pod (tens of thousands of lines per second) must not freeze the UI or grow memory
   without bound.

### Non-goals

- Exec, attach, port-forward (post-v0.1).
- Log aggregation across clusters, or from logging backends (Loki, CloudWatch, ...).
- Parsing structured logs (JSON fields as columns). Lines are shown as text.
- Rendering ANSI colours. Escape codes are stripped in M3 (see [Line handling](#line-handling)).
- Node or control-plane logs (`/logs` on the kubelet).
- Pods of CronJobs (they belong to its Jobs) and of custom workload types (e.g. Argo Rollouts).

## Proposal

### User experience

```
┌──────────────┬─────────────────────────────┬──────────────────────────────────────────────────┐
│ prod-eu ●    │ Deployments  [ns: web ▾] 🔍  │ web   Describe | YAML | Events | Pods | Logs  ⤢  │
│ Workloads    │ NAME   READY  UP-TO-DATE AGE│ [All containers ▾] [Tail 1000 ▾] [Since ▾]       │
│  Pods        │ web    3/3    3          3d ◀│ ☑ Follow ☐ Previous ☐ Timestamps ☐ Wrap  ⤓      │
│  Deployments◀│ api    1/1    1          9d │ 🔍 timeout        [Aa] [.*] [Only matching] 2/14 │
│  ...         │                             │ web-7d9f-x2  app  GET /health 200                │
│              │                             │ web-7d9f-k8  app  upstream timeout after 30s     │
│              │                             │ web-7d9f-x2  app  GET /orders 504                │
│              │                             │ ── web-7d9f-k8/app restarted ──                  │
│              │                             │                          [↓ Jump to latest]      │
└──────────────┴─────────────────────────────┴──────────────────────────────────────────────────┘
```

- Pods and the five workload kinds get a **Logs** tab. Workloads also get a **Pods** tab, a
  live table of their pods; clicking a row opens that pod in the panel.
- Opening the Logs tab starts streaming the last **1,000 lines** per container with follow on.
  The container defaults to the pod's `kubectl.kubernetes.io/default-container` annotation,
  then to its first container, like `kubectl logs`. For a workload the same rule is applied to
  its pod template.
- The **⤢** button maximizes the detail panel over the table, since logs need width. Esc or ⤢
  restores it.
- Scrolling up pauses auto-scroll (the stream keeps running) and shows **Jump to latest**.
- Changing an option restarts the stream with the new options; the old lines are cleared.
- Container restarts and stream gaps are marked inline (`── web-7d9f-k8/app restarted ──`,
  `── disconnected, resumed ──`).
- Workload logs stream at most **10 pods** at a time. Beyond that a notice says how many pods
  are not shown and the container picker gains a pod picker to choose which ones.
- **Download (⤓)** opens a save dialog and writes the full log (not just what is loaded) with
  the current container, previous and timestamps options.
- Per-source problems (no permission for `pods/log`, container still creating, pod gone) show
  in a status strip above the lines without stopping the other sources.

## Design details

### Package layout

Logs is its own area, next to `resources`, and depends on `resources` only for shared types
(`ObjectRef`, `ResourceType`):

```
internal/resources/
  workload/          PodSelector: a workload's label selector (Pods tab and logs)
internal/logs/
  types.go           Request, Line, Batch, Status, DownloadRequest
  interfaces.go      Opener, PodWatcher, Sink
  kube/              Opener and PodWatcher over client-go (GetLogs, pod watch)
  stream/            a stream = targets → per-container readers → merger → batcher
  download/          writes a target's full logs to an io.Writer
```

Following the design principles of proposal 0002 (SOLID, replaceable parts), `stream` and
`download` depend only on the interfaces in `internal/logs`, and only `kube` calls client-go.

### Pods of a workload

- **`workload.PodSelector`** returns the label selector of a workload:

  ```go
  // PodSelector returns the selector of the pods that ref manages, or
  // ErrNoPods if ref's type does not manage pods.
  type PodSelector interface {
      Selector(ctx context.Context, s cluster.Session, ref resources.ObjectRef) (labels.Selector, error)
  }
  ```

  The implementation GETs the object with the dynamic client and converts `spec.selector`
  (`metav1.LabelSelector`, with `matchExpressions`) using `metav1.LabelSelectorAsSelector`.
  Supported kinds are a data table: `apps/v1` Deployment, StatefulSet, DaemonSet, ReplicaSet,
  and `batch/v1` Job. An empty selector is rejected rather than matching every pod.
- **Pods tab:** `cache.Key` gains `LabelSelector` beside `FieldSelector`, and `table.Source`
  passes it on LIST and WATCH. The tab is an ordinary view on `pods` in the workload's
  namespace with that selector, so it is live, shares the informer cache, and uses the same
  `RowGrid`. The selector string is canonical (`labels.Selector.String()` sorts terms), so one
  workload always maps to one informer.
- **Precision:** like `kubectl describe` and `kubectl logs -l`, pods are matched by selector
  only. Overlapping selectors (two workloads selecting the same pods) show the union. This is
  rare and almost always a misconfiguration, so we do not also walk owner references.
- The selector is read again when the workload's `resourceVersion` changes (at most once per
  2s, like Describe). A changed selector reopens the view.

### Log streams

A **stream** is one open Logs tab: `(target, options)`. The target is a pod or a workload.

- **Targets:** for a pod, one pod. For a workload, the pods its selector matches. In both
  cases `stream` asks a `PodWatcher` for the pods as **full objects**, because it needs
  container names, states and restart counts, which the M2 table rows do not carry. `kube`
  implements it with one filtered watch per stream (`metadata.name=<pod>` or the label
  selector, in one namespace). This is separate from the table cache on purpose: it stores few
  objects, lives exactly as long as the tab, and keeps `cache` free of full objects.
- **Sources:** each `(pod, container)` is a source with its own reader, opened through
  `Opener` (client-go `Pods(ns).GetLogs(name, opts).Stream(ctx)`). The request always sets
  `timestamps: true`; the backend parses and strips the timestamp, so the UI can show or hide
  it without restarting, and resume can use it. A source is opened when its container has
  started (running or terminated). Waiting containers show as "waiting: ContainerCreating" in
  the status strip.
- **Workload cap:** at most **10 pods** per stream, chosen running-first, then newest.
  `kubectl logs -l` has a similar cap (`--max-log-requests`, default 5) for the same reason:
  each source is one long-lived request on the API server. The user can pick other pods.
- **Merging:** lines are forwarded in arrival order. Lines from one source keep their order;
  lines from different sources are not re-sorted by timestamp (that would need a delay to wait
  for late sources). Download does sort them (see [Download](#download)).
- **Container restarts:** while following, the kubelet ends a log request when the container
  exits. When the pod watch shows that container running again with a higher
  `restartCount`, the source reopens with `sinceTime` set to its last line's timestamp and
  emits a `restarted` marker.
- **Connection drops:** every stream's context is a child of `Session.Ctx`, so a disconnect
  ends all its sources and the stream reports `stale`. The UI keeps the lines. When M1
  reconnects, the UI restarts the stream with `resume: true`; each source reopens with
  `sinceTime` = its last timestamp and skips lines it already sent (the same timestamp and
  the same count of lines at that timestamp). A `resumed` marker shows where the gap was.
- **Ending:** a stream ends when its tab closes (`Stop`), its target is deleted, or follow is
  off and every source reached EOF.

### Line handling

- Lines are split on `\n`, with `\r\n` normalized. A line longer than **16 KiB** is cut and
  ends with `… [N bytes truncated]`, so one giant line cannot blow up memory or the renderer.
- Invalid UTF-8 is replaced with U+FFFD. ANSI escape sequences are stripped, so search matches
  what is shown. Rendering colours is a possible follow-up.
- **Batching:** like table views, each stream flushes at most every **100ms**, with at most
  **5,000 lines per batch**. If more lines than that arrive within one window, the oldest are
  dropped and the batch reports `dropped`, shown inline as `── 12,345 lines skipped (output
  too fast) ──`. Download is never affected by this.
- **UI buffer:** the UI keeps the newest **50,000 lines** per stream and drops older ones
  (noted at the top: "Older lines are not loaded. Download for the full log.").

### Download

- `Download` opens the native save dialog (Wails `Dialog.SaveFile()`), then writes from Go
  straight to the file. Nothing passes through the UI, so size is not limited by the buffer.
- It requests the full log (no tail, no since, no follow) with the current container,
  previous and timestamps options.
- For a workload, each source is read fully, then lines from all sources are merged by
  timestamp and written with a `pod/container` prefix. Sources are read one after another so a
  download adds at most one request at a time.
- Default file name: `<pod-or-workload>[-<container>]-<YYYYMMDD-HHMMSS>.log`.
- The UI shows progress (bytes written) and can cancel; a cancelled download deletes the
  partial file.

### Go<->UI contract

New service `app.LogService`, a thin wrapper over `internal/logs`, and one new method on
`ResourceService`:

```go
func (s *LogService) Containers(ref resources.ObjectRef) (logs.Containers, error)
func (s *LogService) Start(req logs.Request) error // lines and status arrive as events
func (s *LogService) Stop(streamID string)
func (s *LogService) Download(req logs.DownloadRequest) (string, error) // path written, "" if cancelled
func (s *LogService) CancelDownload(downloadID string)

func (s *ResourceService) OpenPods(viewID string, ref resources.ObjectRef) error
```

As with views, the UI chooses the stream ID and routes events for it before calling `Start`.
Changing options is `Stop` + `Start` with a new ID; an in-place update is not worth the code.

Types sent to the UI:

```go
type Containers struct {
    Default    string      `json:"default"`
    Containers []Container `json:"containers"`
    Pods       []string    `json:"pods,omitempty"` // workloads only, for the pod picker
}

type Container struct {
    Name string `json:"name"`
    Kind string `json:"kind"` // container | init | ephemeral
}

type Request struct {
    StreamID     string              `json:"streamId"`
    Target       resources.ObjectRef `json:"target"`    // a pod or a workload
    Container    string              `json:"container"` // "" = default, "*" = all containers
    Pods         []string            `json:"pods,omitempty"` // workloads: chosen pods; empty = automatic
    Follow       bool                `json:"follow"`
    Previous     bool                `json:"previous"`
    TailLines    int64               `json:"tailLines"`    // per container; 0 = all
    SinceSeconds int64               `json:"sinceSeconds"` // 0 = no limit
    Resume       bool                `json:"resume"`       // continue a stale stream
}

type Line struct {
    Source int       `json:"s"` // index into Status.Sources
    Time   time.Time `json:"t"`
    Text   string    `json:"x"`
}

type Batch struct {
    StreamID string   `json:"streamId"`
    Lines    []Line   `json:"lines"`
    Markers  []Marker `json:"markers,omitempty"` // restarted, resumed; placed by line index
    Dropped  int      `json:"dropped,omitempty"`
}

type Status struct {
    StreamID string         `json:"streamId"`
    Phase    string         `json:"phase"` // starting | streaming | ended | stale | error
    Sources  []SourceStatus `json:"sources"`
    Hidden   int            `json:"hidden,omitempty"` // workload pods over the cap
    Message  string         `json:"message,omitempty"`
}

type SourceStatus struct {
    Pod       string `json:"pod"`
    Container string `json:"container"`
    Phase     string `json:"phase"` // waiting | streaming | ended | forbidden | error
    Message   string `json:"message,omitempty"`
}
```

Lines refer to their source by index (short JSON keys too), so a busy workload stream does not
repeat pod and container names on every line. New sources are appended, so indexes never
change during a stream; `Status` is re-sent whenever the source list or a phase changes.

Events:

| Event | Payload | When |
|---|---|---|
| `logs:lines` | `Batch` | ≤10/s per stream |
| `logs:status` | `Status` | sources added or changed, phase changes |
| `logs:download` | `{downloadId, bytes, done, error}` | progress, at most 4/s |

### Frontend

Under `frontend/src/lib/logs/`:

- `LogsTab.svelte` is a detail tab (`DetailTabProps`) with the toolbar, status strip, search
  bar and the log view. `PodsTab.svelte` in `resources/detail/` wraps `RowGrid` like the
  Events tab.
- `logs.svelte.ts` holds the stream store: the ring buffer (50,000 lines), source list,
  markers, and search state. Search runs over the buffer in a worker-free loop chunked with
  `requestIdleCallback`, and new lines are matched as they arrive.
- **The log view uses the existing editor module.** `lib/editor` gains `language: 'log'` and a
  small imperative API for streaming text, so CodeMirror's virtualized rendering, line
  wrapping, selection and copy are reused, and the rest of the app still imports only
  `CodeEditor.svelte`:

  ```ts
  export interface LogViewHandle {
    append(lines: string[]): void;   // trims from the top past the buffer limit
    clear(): void;
    setDecorations(d: LogDecorations): void; // source prefixes, markers, search matches
    scrollToEnd(): void;
  }
  ```

  The pod/container prefix and timestamps are decorations, not text, so toggling them does not
  rebuild the document. "Only matching" swaps in a document built from the matching lines.
- Options the user changes (tail, timestamps, wrap) are remembered app-wide in settings.

### Security and RBAC

- Reading logs needs `get` on `pods/log`; the Pods tab and the pod watch need `list` and
  `watch` on `pods` in the namespace. A `403` marks the affected source or tab as forbidden,
  the same way M2 handles forbidden namespaces. No access reviews are needed: logs are
  read-only, and RBAC-aware disabling of actions comes with M4.
- Log content is the user's data and is shown as is. It is not sent anywhere and not written
  to KubeRoot's own logs. Error messages pass through `internal/redact`.
- Downloads are written only to the path the user picks in the save dialog.

### Performance

- API load: one long-lived request per streamed container (HTTP/2 multiplexed on the existing
  connection) plus one filtered pod watch per open Logs tab. With the 10-pod cap and one open
  panel, a workload with two containers is at most 21 requests.
- Backend memory: only the pending batch (≤5,000 lines) per stream; lines are not stored.
- UI memory: 50,000 lines × ~200 bytes ≈ 10 MB per open stream; only one panel is open at a
  time.
- Target: a source writing 20,000 lines/s keeps the UI responsive (scroll, search, typing) on
  all three platforms, with skipped lines reported.

## Test plan

- **`workload`:** selector conversion for each kind (matchLabels, matchExpressions), empty and
  missing selectors, unsupported kinds.
- **`table` / `cache`:** label selector on LIST/WATCH and in the informer key.
- **`stream`:** with fake `Opener` and `PodWatcher`: line splitting, long lines, invalid
  UTF-8, ANSI stripping, the batcher (100ms window, 5,000-line cap, `dropped`), source indexes,
  the workload cap and pod choice, restart reopen with `sinceTime`, resume de-duplication on
  equal timestamps, cancellation via `Session.Ctx`, and a `403` on one source.
- **`kube`:** an `httptest` API server serving `/log` with chunked follow output, `previous`,
  and errors (`400` container not found, `403`).
- **`download`:** full read, timestamp merge across sources, cancel removes the file.
- **`app`:** `LogService` with the injected `emit`, as for the other services.
- **Integration (kind, CI):** a pod printing a counter; follow, restart it (kill the
  process), check no line is lost or repeated; a 3-replica Deployment scaled to 5 and back to
  1, checking sources come and go; a ServiceAccount without `pods/log`.
- **Manual:** kind, EKS and GKE (M1 follow-up 1), on macOS, Windows and Linux: a noisy pod
  (20k lines/s), long lines, Wi-Fi off and on while following, download of a large log.

## Alternatives

- **An in-house virtualized log list** (like `RowGrid`): smaller, but fixed row heights make
  line wrap hard, and we would rebuild selection, copy and find. CodeMirror is already in the
  app behind `lib/editor`.
- **Sorting merged workload lines by timestamp while streaming:** needs a reorder delay and
  still fails for late sources. Arrival order is what `stern` and `kubectl logs -l` show.
- **Downloading what the UI has loaded:** simple, but truncated by the buffer. Full download
  from Go is not much more work. A "save loaded lines" option could be added later.
- **Pod lists from the table cache instead of a separate watch:** table rows carry only cells
  and metadata, not container statuses. Storing full pods in `cache` would cost memory for
  every pod table.

## Open questions

1. **Workload pod cap:** 10 pods per stream, or follow kubectl's default of 5?
2. **Defaults:** 1,000 tail lines per container, follow on, timestamps off, wrap off?
3. **Services:** a Service's `spec.selector` (a plain map) selects pods too. Add Services to
   the Pods and Logs tabs now (a few lines in the kind table), or leave it for later?
4. **Save loaded lines:** besides the full download, also offer saving the lines currently
   loaded (respecting "Only matching")?
